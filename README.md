# TraceMark: Privacy-Preserving Provenance for AI-Generated Images

> Asymmetric-cryptography mini project. Built by extending
> [StegoVault](https://github.com/nabirudd/StegoVault-LSB-Steganography-Tool) (LSB steganography, Flask).

**Problem.** Morphed and deepfake images (including non-consensual nude images of women) circulate on social media,
and victims and police have no way to trace who created them. India's IT Rules amendment of 10 Feb 2026 now requires
AI-generated content to carry labels and provenance metadata that cannot be stripped out.

**Solution.** Every image produced by a participating AI platform carries an invisible, **signed** and
**encrypted** provenance tag:

* **The public** can verify that an image is *AI-generated by PixelForge* (signature check with a public key).
* **The creator's identity** (account, phone, IP, location) is sealed. Only the **Cyber Police**, and only with a
  **court warrant**, can decrypt it.
* The tag **survives WhatsApp forwarding, screenshots and re-compression**, and **cannot be forged or moved** onto
  another photo.

## 1. Run it

### Windows
Double-click **`run_windows.bat`**. It creates a virtual environment, installs requirements and starts the server.

### Mac / Linux
```bash
./run_mac_linux.sh
```

### Manual
```bash
python -m venv .venv
.venv\Scripts\activate          # Windows   (source .venv/bin/activate on Mac/Linux)
pip install -r requirements.txt
python app.py
```
Open **http://127.0.0.1:5000**. Python 3.9+ required.

The key pairs are generated in `keys/` on first run. The demo data lives in `data/`. Use **Reset demo data** on the home page to start over.

| Role | Passphrase (demo) |
|---|---|
| Cyber Police private key | `police@123` |
| Court private key | `court@123` |
| Platform signing key | `platform@123` (used automatically by the server) |

### Tests and security analysis
```bash
python -m pytest -v                       # 24 automated tests
python analysis/security_analysis.py      # writes analysis/results.md + robustness.csv
```

## 3. Architecture

```
          ┌───────────────────── PixelForge AI (platform) ─────────────────────┐
 prompt → │ generate → [Layer B] robust DCT watermark (64-bit record ID + CRC) │
          │          → pHash → public part {label, platform, time, pHash, id}  │
          │          → identity ──AES-256-GCM(K, aad=public)──► ct             │
          │            K = s1 ⊕ s2 ; RSA-OAEP(Police_pub, s1), RSA-OAEP(Court_pub, s2)
          │          → Ed25519 sign(public ‖ sealed)                           │
          │          → [Layer A] LSB-embed envelope  + store in registry       │
          └───────────────────────────────┬────────────────────────────────────┘
                                          ▼
   SocialSphere (forward / screenshot: JPEG re-compression destroys Layer A, Layer B survives)
                                          ▼
   Verifier / Police:  Layer A?  ──no──►  Layer B → record ID → registry → envelope
                       verify Ed25519 · ID match · pHash distance ≤ 12  → verdict
                                          ▼
   Court:   s2 = RSA-dec(Court_priv) → RSA-OAEP(Police_pub, s2) → RSA-PSS signed warrant
                                          ▼
   Police:  s1 = RSA-dec(Police_priv), s2 from warrant → K = s1 ⊕ s2 → AES-GCM decrypt identity
```

### Algorithms
| Purpose | Algorithm | Library |
|---|---|---|
| Tag authenticity / non-repudiation | **Ed25519** | `cryptography` |
| Identity confidentiality | **RSA-3072-OAEP (SHA-256)** + **AES-256-GCM** (hybrid) | `cryptography` |
| Judicial oversight | **2-of-2 key split** (XOR) between the Police and Court keys | — |
| Warrant authenticity | **RSA-3072-PSS** | `cryptography` |
| Private-key storage | PKCS#8 PEM, passphrase-encrypted | `cryptography` |
| Fragile layer | LSB steganography (from StegoVault, vectorised) | NumPy, Pillow |
| Robust layer | Block-DCT QIM watermark on a normalised 512×512 luminance grid, ×256 redundancy + majority vote | NumPy |
| Anti-transplant | 64-bit DCT perceptual hash, signed | NumPy |
| Real-time updates | Server-Sent Events | Flask |

### Project layout
```
app.py                    Flask app: all 6 role pages + live event stream
tracemark/crypto_core.py  keys, Ed25519, RSA-OAEP/PSS, AES-GCM, key split

```

## 4. Security analysis summary
Run `analysis/security_analysis.py` for fresh numbers. A sample run on 4 images:

* **Imperceptibility:** PSNR 38.7–39.3 dB, SSIM 0.92–0.94. The envelope is 1.65 KB.
* **Robustness:** verified after JPEG quality 95 down to 50 (quality 30 usually survives but not always), the WhatsApp forward simulation, screenshot-repost, 50% downscale (with or without JPEG), 150% upscale, brightness change and blur. The tag is **lost** after cropping or rotation.
* **Attacks blocked:** forged tag, tampered identity, edited label, transplanted tag, police unmasking without a warrant, fake warrant, guessed key passphrase.
* **False positives:** 0 of 4 untagged images (16-bit CRC + registry + pHash filtering).

### Limitations (state these in the report)
1. Only works for **participating** platforms. A model run locally on someone's own computer adds no tag. This is a policy problem as much as a technical one, and it is what the IT Rules 2026 mandate addresses.
2. Cropping, rotation and strong adversarial attacks can remove the robust watermark. Future work: geometric-resilient watermarks (e.g. Adobe TrustMark, StegaStamp) and server-side fingerprint matching.
3. The registry is a trusted, centralised service. Future work: a transparency log or blockchain anchoring.
4. The 2-of-2 split is a simple threshold scheme. Future work: Shamir *k-of-n* across several authorities.
5. All people, accounts and IPs in the demo are **fictional**. Use sample images, or only photos you have permission to use.
